# Agent Spec: analytics-copilot

## Overview
`analytics-copilot` is an advanced AI analytics assistant built on Google ADK 2.0 Dynamic Graph Workflows. It handles analytical questions from business stakeholders (e.g., *"Why have credit card balances dropped in Q3?"*), clarifies missing requirements, dynamically generates 1 to 7 testable hypotheses with a common base cohort/denominator, executes NL2SQL queries concurrently using a runtime parallel worker, and synthesizes/ranks the findings into a comprehensive executive narrative.

## Architecture & Graph Topology

```
                  ┌──────────────────────────────┐
                  │            START             │
                  └──────────────┬───────────────┘
                                 │
                                 ▼
         ┌────────────────────────────────────────────────┐
         │      Clarification & Hypothesis Planner        │
         │  - Clarifies ambiguities if needed (HITL)     │
         │  - Defines common cohort/denominator filters   │
         │  - Generates 1 to 7 structured hypotheses/SQLs │
         └───────────────────────┬────────────────────────┘
                                 │ list[HypothesisTask] (dynamic length 1-7)
                                 ▼
         ┌────────────────────────────────────────────────┐
         │     Parallel Worker: SQL & Data Investigator   │
         │          @node(parallel_worker=True)           │
         │  - Generates NL2SQL per hypothesis             │
         │  - Executes query via BigQuery/SQL tool        │
         │  - Extracts metrics & evidence                 │
         └───────────────────────┬────────────────────────┘
                                 │ list[HypothesisResult]
                                 ▼
         ┌────────────────────────────────────────────────┐
         │        Hypothesis Synthesizer & Evaluator      │
         │  - Evaluates & validates evidence per hypothesis│
         │  - Ranks contributing factors                  │
         │  - Assesses sufficiency vs. deep-dive needed   │
         │  - Generates executive narrative report        │
         └────────────────────────────────────────────────┘
```

### Graph Nodes
1. **`PlannerNode` (Clarification & Hypothesis Generation)**:
   - Understands business query intent.
   - If critical information is missing, can request input or clarify context.
   - Establishes a shared baseline (cohort filters, time range, denominator) to ensure apples-to-apples comparison across all queries.
   - Outputs a list of 1 to 7 `HypothesisTask` objects (dynamic width).

2. **`ParallelInvestigatorNode` (`@node(parallel_worker=True)`)**:
   - Dynamically scales concurrency at runtime based on the number of hypotheses generated (0 to 7).
   - Equips each worker with NL2SQL generation and BigQuery query execution tools.
   - Runs queries and returns structured `HypothesisResult` with metrics and observations.

3. **`SynthesizerNode` (Hypothesis Evaluator & Narrator)**:
   - Receives `list[HypothesisResult]`.
   - Evaluates each hypothesis against retrieved data to verify or refute it.
   - Ranks contributing factors by impact.
   - Assesses if evidence is sufficient or flags recommended deep dives.
   - Narrates the comprehensive executive analysis to the user.

## Data Schemas

### 1. `HypothesisTask` (Pydantic Model)
- `id`: str (e.g., `"H1"`)
- `title`: str (e.g., `"High-balance customer attrition"`)
- `rationale`: str
- `base_filters`: dict[str, Any] (e.g., date range, active credit card accounts)
- `target_metric`: str
- `sql_intent`: str

### 2. `HypothesisPlan` (Pydantic Model)
- `clarification_needed`: bool
- `clarification_question`: Optional[str]
- `business_question`: str
- `common_base_cohort`: str
- `hypotheses`: list[HypothesisTask]

### 3. `HypothesisResult` (Pydantic Model)
- `hypothesis_id`: str
- `generated_sql`: str
- `query_status`: str (SUCCESS / FAILED)
- `data_summary`: dict[str, Any]
- `key_findings`: str

### 4. `AnalyticsSynthesis` (Pydantic Model)
- `executive_summary`: str
- `ranked_hypotheses`: list[dict[str, Any]] (rank, id, verdict: CONFIRMED / REFUTED / INCONCLUSIVE, contribution_pct, impact)
- `sufficiency_verdict`: str (SUFFICIENT / DEEP_DIVE_RECOMMENDED)
- `recommended_next_steps`: list[str]
- `narrative_report`: str

## Tools Required
- `execute_bigquery_query`: Tool to validate and execute analytical SQL queries against the dataset (with built-in simulated/in-memory BigQuery schema for local development and testability).
- `get_table_schema`: Tool to inspect available tables, column definitions, and sample rows.

## Constraints & Safety Rules
- Dynamic fan-out bound between 1 and 7 parallel workers to prevent runaway execution.
- Read-only queries (SELECT only, no DDL/DML mutation).
- Deterministic data consistency: all parallel hypothesis queries inherit the common cohort base filters.
- Proper handling of empty result sets or query exceptions.

## Success Criteria
- Scaffolded project cleanly created with `agents-cli`.
- ADK 2.0 dynamic workflow graph executes cleanly end-to-end.
- Runtime dynamic parallelism accurately scales to the number of generated hypotheses (1-7).
- Synthesizer generates structured ranking, sufficiency decision, and narrative output.
- Unit and eval tests validate graph construction, tool execution, and synthesis quality.

## Assumptions
- Prototype-first mode without initial cloud deployment scaffolding (`--prototype`).
- Local environment includes a simulated BigQuery table schema (banking/credit card metrics) for offline testing and evaluation.
